# Veles Tools 2.18 — сборка с новым оптимизатором

Исходники в `extension/ui/src` заканчиваются на версии 2.3.3, а рабочее расширение — 2.14.0
(в репозитории его исходников нет, был только собранный zip). Эта папка — способ менять 2.14.x
дальше с нормальным diff:

| Путь | Что это |
| --- | --- |
| `extension/` | распакованное расширение 2.14.0 (манифест, скрипты, html, иконки, css) |
| `app/bundle.js` | JS-бандл приложения 2.14.0, отформатированный prettier — редактируется напрямую |
| `src/patternSearch.mjs` | новый пошаговый поиск и оценка «лучше по обоим» (чистые функции, с тестами) |
| `src/modes.mjs` | режимы-вкладки 2.16: шаблоны скальпера/SHORT/LONG, зеркало для SHORT, абсолютная оценка, подбор монет (чистые функции, с тестами) |
| `build.mjs` | сборка: esbuild бандлит `app/bundle.js` + `src/`, минифицирует, кладёт в `dist/extension` и zip в `release-artifacts/` |
| `test/` | unit-тесты модуля, имитация рынка и veles.finance, сквозные прогоны в Chromium |

Первый коммит с папкой — нетронутый 2.14.0, поэтому `git diff` по `app/bundle.js` показывает ровно
изменения оптимизатора.

```bash
npm run build:extension          # → release-artifacts/veles-tools-optimizer-<версия>.zip
npm run test:extension           # unit-тесты src/patternSearch.mjs и src/modes.mjs

# сквозные прогоны (нужны playwright-core и Chromium):
node extension-build/build.mjs --test
node extension-build/test/e2e/run.mjs --months=0          # движок целиком на имитации рынка
node extension-build/test/e2e/run.mjs --goal=scalper --minDealsRate=0   # режим: scalper|short|long|coins
node extension-build/test/e2e/run.mjs --method=grid --onlyKinds=takeProfit,pullUp --rerun=true   # перебор + повтор из памяти
node extension-build/test/e2e/run.mjs --certify=true --onlyKinds=takeProfit,pullUp,conditionValue --budget=40   # сертификат
node extension-build/test/e2e/ui.mjs --shots=/tmp/shots   # весь интерфейс: запуск, итоги, скриншоты
node extension-build/test/e2e/ui_modes.mjs --shots=/tmp/shots --tabs=scalper,coins   # вкладки режимов
node extension-build/test/e2e/evaluator.mjs              # быстрый пересчёт портфеля = «Группы бэктестов»
```

## Что нового в 2.18.0: аудит — одни и те же монеты, честное сравнение, надёжный опрос Veles

Полный аудит оптимизатора (путь запуска, математика оценки, запросы к Veles). Главное:

**Монеты, на которых не запускается исходная** (чаще всего ордер меньше минимального на бирже при
депозите бэктестов). Раньше такая монета попадала в финальную проверку каждого варианта, и все
финалисты получали «Бэктест не выполнен» — итог «ничего не лучше исходной» был ложным, а «Сравнить в
группах» брал вариант, проверенный только на 12 монетах поиска (группы «50 против 12»). Теперь:
исходная перезапускается на таких монетах один раз, оставшиеся убираются из сравнения для всех
(`vtExcluded`, сохраняется в состоянии), монеты поиска берутся только из тех, где исходная работает.

**Вариант не запускается на нескольких монетах, где исходная работает** (уменьшенный объём ордера):
- до 10% монет — вариант сравнивается с исходной на тех же монетах, где он работает, и помечается
  «не запускается: …» (в логе, на карточке, сравнение на карточке — с исходной на тех же монетах);
- больше — вариант не проходит, в логе сказано, что именно Veles его не запускает;
- если так провалились все финалисты, на всех монетах проверяются следующие по оценке; бэктесты с
  ошибкой Veles повторяются один раз (в поиске, финале, плато).

**Таблица и действия.** В «Лучших вариантах» всегда есть все варианты, проверенные на всех монетах
(раньше непрошедшие финалисты вытеснялись непроверенными). «Сравнить в группах» берёт только вариант,
проверенный на всех монетах; обе группы — на одних и тех же монетах, в названии — число монет и
множитель депозита, группа открывается с лимитом позиций оптимизатора (раньше страница групп
подставляла 3). Графики в «Подробнее» — при том же депозите, что и таблица.

**Оценка.**
- Исходная оценивается ровно как есть: если её значения не попадали на сетку шагов, поиск считал
  «исходной» округлённую копию, и сравнение «лучше по обоим» тихо превращалось в обычный P/R без
  проверки числа сделок и срезов.
- Срезы поиска: периоды и группы монет оцениваются отдельно, берётся худший из двух типичных
  результатов; при чётном числе срезов — нижнее из двух средних значений (раньше группы монет
  маскировали плохие полугодия, а из двух срезов бралось среднее).
- Поиск на части монет: депозит и лимит позиций масштабируются на долю монет поиска — блокировка и
  ограничение просадки в % депозита работают как на полном списке.
- Вкладки-шаблоны: просадка меньше 1% депозита считается за 1% — почти не торгующий вариант больше
  не выигрывает по прибыли/просадке.
- «Устойчивого улучшения не найдено…подгонка» больше не пишется, когда на всех монетах ни один
  вариант просто не обошёл исходную; один допуск 2% «не хуже» в таблице, логе и вердикте.

**Запросы к Veles.**
- Результат, принятый без финального статуса Veles (статус «завис» или недоступен), используется, но
  хранится в памяти 6 часов, а не бессрочно.
- Время без связи со вкладкой veles.finance не съедает лимит ожидания бэктеста (до 3 ч); после
  перезапуска бэктест, который ещё в очереди, не запускается заново через 5 минут.
- Поиск дубля после «запрос мог выполниться» сверяет и период (одно имя `Opt_…` у периода поиска,
  финала и стресс-теста).
- Тип ошибки — по HTTP-статусу, а не по цифрам в тексте; один бэктест, который Veles не принимает
  после всех повторов, пропускает монету, а не останавливает запуск, если другие принимаются.
- Отказы Veles по одному варианту больше не останавливают запуск («бэктесты подряд с ошибкой»
  считаются отдельно для монет, где исходная работает).
- После фатальной ошибки бэктесты движка отменяются: «Продолжить» не запускает второй движок рядом.
- Даты листинга сохраняются в состоянии; одинаковые бэктесты, запрошенные одновременно, идут один раз;
  незапускаемый тикер пропускает монету.

Сквозной тест: `--failCoins=A,B` (монеты, где Veles не запускает никого) и `--failVariantCoins=C`
(только варианты). Осознанно не менялось (паритет с «Группами бэктестов»): «суммарная просадка» =
max(МПУ одновременных сделок, реализованная просадка), реализованная просадка от первого закрытия.

## Что нового в 2.17.0: постоянная память, полный перебор, сертификат

**Память бэктестов** (IndexedDB `veles-optimizer`, хранилище `results`). Каждый бэктест хранится под
ключом из настроек бота, монеты, периода, комиссий и точности; совпал ключ — бэктест не запускается.

- Бэктесты завершённых периодов хранятся бессрочно (в 2.16 — 120 дней); период, который ещё идёт
  (конец в будущем), — 6 часов.
- В ключ больше не входят метаданные бота (`createdAt`, `updatedAt`, `status`, `substatus`,
  `lastFail`, `apiKey`…): в 2.16 переименование, запуск или остановка бота меняли `updatedAt`, и все
  его бэктесты переставали находиться. Записи со старым ключом находятся и пересохраняются под новым.
- Разрешение `unlimitedStorage` и `navigator.storage.persist()` — браузер не вычищает память при
  нехватке места.
- «Конец периода» для «С 2020», «1 год» и т. п.: по умолчанию последний день прошлого месяца — все
  запуски в течение месяца проверяют одни и те же даты и берутся из памяти; «на неделю» — как в 2.16
  (закреплён на 7 дней), «вчера» — самые свежие данные. Настройка общая для вкладок
  (`veles_optimizer_period_anchor_v1`).
- В логе: «🧠 Память: N» и кнопки «Сохранить» (файл `.ndjson.gz` со всеми бэктестами и историей —
  резервная копия, перенос в другой браузер; пишется и читается построчно, поэтому большая память не
  держится в оперативной целиком), «Загрузить» (добавляет недостающие и более новые записи; запись со
  сделками не заменяется записью без них), «История», «Очистить» (удаляет бэктесты, история остаётся;
  с подтверждением).
- **История запусков** (хранилище `history`, база версии 2): каждый завершённый запуск вкладки
  сохраняется (30 последних), любой можно открыть («Показать») — раньше новый запуск затирал итог.

**Полный перебор** («4. Глубина поиска» → «Перебор», `searchMethod: "grid"`,
`psRunGrid` в `src/patternSearch.mjs`). Проверяется каждая комбинация разрешённых значений
включённых параметров: от min до max с шагом, у фильтров — все варианты. Порядок обхода —
перестановка `k·stride mod N`, поэтому остановленный перебор покрывает пространство равномерно.
Одинаковые после согласования параметров (repair) варианты оцениваются один раз. Сетка больше
20 000 комбинаций не запускается (форма показывает число комбинаций заранее). Перебор идёт через архив
и память, поэтому после остановки продолжается с того же места без повторных бэктестов. Только когда
проверены все комбинации и ни один бэктест не завершился ошибкой, в логе — «✅ Гарантия перебора»: на
монетах и периоде поиска лучше найденного нет ни одной. Варианты с неудавшимся бэктестом не попадают в
архив, и повторный запуск проверяет только их. Финалисты, как и после пошагового поиска, проверяются на всех монетах.

**Сертификат** (переключатель «Сертификат лучшего» у пошагового поиска, `psCertify`). После поиска
каждый параметр лучшего варианта проверяется по всем разрешённым значениям при остальных
фиксированных; если какое-то значение лучше (больше чем на `margin` = 0.0025 оценки) — переходим
туда и проверяем заново, до 3 проходов. Итог «✅ Сертификат»: ни одно изменение одного параметра не
улучшает результат. Это гарантия локальной (покоординатной) оптимальности на монетах и периоде
поиска; проход стоит Σ(значений − 1) вариантов (например, 737 у бота с 7 ордерами и фильтром).

Почему не «перебрать всё» всегда: у такого бота по умолчанию 19 параметров и ≈ 4·10²⁵ комбинаций —
даже по секунде на комбинацию это дольше возраста Вселенной. Поэтому полный перебор — для 2–4
параметров с разумным шагом, а для всего пространства — пошаговый поиск с сертификатом.

## Что нового в 2.16.0: вкладки оптимизатора

Страница «Оптимизатор» разделена на вкладки (`#/optimizer/<вкладка>`), у каждой свои настройки,
прогон, сохранённое состояние и итоги. Одновременно идёт один прогон — остальные вкладки
предупреждают и не запускаются; вкладка с прогоном помечена ⏳, а открытая заново страница
подключается к идущему прогону.

| Вкладка | Что делает |
| --- | --- |
| 🎯 Улучшить стратегию | как в 2.15: пошаговый поиск от вашего бота, «лучше и по прибыли, и по просадке» |
| ⚡ Скальпер | собирает скальпер с нуля: 1–5 ордеров, тейк ~0.5%, стоп, вход по RSI/CCI на 1/5/15 мин, LONG или SHORT; по умолчанию — последний год |
| 📉 Шорт-бот | SHORT-зеркало вашего LONG-бота (пороги RSI/CCI/MFI/… отражаются, сетка — вверх от цены) или SHORT DCA-шаблон |
| 📈 LONG DCA с нуля | DCA-сетка из шаблона (классическая / плотная / широкая) и фильтры входа |
| 🪙 Подбор монет | бот без изменений на каждой монете списка (ботов, широкий ~150 монет Bybit или свой) и лучший набор по сделкам этих бэктестов — без новых бэктестов |

**Шаблон строится на выбранном боте.** Из бота берутся биржа, тип пары, депозит, плечо, тип маржи,
`settings.type`/`indentType`, тип тейка и форма стопа — enum-значения Veles не выдумываются.
Генерируются сетка, условия входа, значение тейка и отступ стопа. Дальше работает движок 2.15:
пошаговый поиск по параметрам шаблона (диапазоны абсолютные: тейк, стоп, подтяжка, отступы,
объёмы, пороги индикаторов), замена и добавление фильтров из пула индикаторов с порогами.

**Абсолютная оценка** для шаблонных вкладок — сравнивать не с чем: прибыль портфеля / суммарная
просадка × (0.5 + 0.5 × доля прибыльных срезов поиска). Выше 50 отношение плавно сжимается к 100,
чтобы варианты не упирались в потолок. Ограничения: суммарная просадка ≤ 35%; у скальпера ещё
средняя сделка ≤ 24 ч и ≥ 2 сделок на монету в месяц. Вердикт устойчивости тоже абсолютный:
прибыль на всех монетах за весь период, в ≥ 80% лет, на монетах вне поиска, до периода поиска
и на стресс-списке, плато ≥ 60%. Фильтры для SHORT отражаются (RSI < 30 → RSI > 70); сравнения
«индикатор против индикатора» (цена выше EMA) остаются как есть — об этом предупреждают карточка
и лог.

**Подбор монет**: исключение монет раундами. В раунде пересчитывается портфель без каждой из
12 самых подозрительных монет (сначала уже известные как вредные, затем — с наименьшей
собственной прибылью и самой глубокой просадкой сделки); все монеты, без которых портфель лучше,
убираются разом, если так портфель лучше, чем без одной самой вредной. Поиск заканчивается, когда
каждая монета текущего набора проверена без прироста. Затем убранные монеты пробуются вернуть
по одной.
Портфель считается так же, как «Группы бэктестов» (блокировка, динамическая блокировка).
Подбор асинхронный: страница не зависает, «Стоп» работает, пересчётов не больше 200–400
(результаты наборов кэшируются). Пересчёт портфеля для подбора — тот же алгоритм, что у «Групп
бэктестов», но по заранее отсортированным сделкам и маске монет (~150× быстрее: 150 монет —
8 мс вместо 1.2 с); он сверяется с точным расчётом на полном списке и при расхождении подбор
переходит на точный.

**Быстрый пересчёт портфеля везде, где не нужны графики.** Оценка каждого варианта и отчёты об
устойчивости (годы, монеты вне поиска, стресс-тест) считались функцией «Групп бэктестов», которая
строит таймлайн и графики для каждой сделки: на 150 монетах и 100+ тыс. сделок это секунды на
вызов и зависшая на минуты страница во время стресс-теста. Теперь — точная копия её расчёта без
графиков (те же метрики, статистика по монетам, число сделок; ~35× быстрее). Первый вызов за
сессию считается обоими способами и сравнивается; при любом расхождении оценка до конца сессии
идёт старым способом. `test/e2e/evaluator.mjs` сравнивает оба способа на случайных портфелях,
`run.mjs --verifyScoring` — на каждом вызове прогона.

**Кэш результатов в памяти ограничен.** Зеркало кэша бэктестов в памяти страницы хранило все
результаты со всеми сделками до конца сессии: на долгом прогоне (LONG-шаблон с 2020 года и
стресс-тестом — 2100 результатов, 6.8 млн сделок) страница доходила до ~4 ГБ и падала. Теперь в
памяти держится не больше ~300 тыс. сделок (давно не использованные результаты вытесняются), сами
результаты остаются в IndexedDB и читаются оттуда при необходимости — бэктесты не повторяются. Проверка: набор, выбранный по первым двум третям периода,
сравнивается со всеми монетами на последней трети. Готовый список — «Скопировать список» или
«Создать бота с этими монетами».

Что не проверено на настоящем Veles (имитация рынка этого не покажет): формат условий шаблона
(простые `conditions`, как у ботов без групп условий), стоп у бота, где его не было (объект
стопа собирается с полями по умолчанию), скальпер-профиль «один ордер» (сетка без усреднений), сигнальные
индикаторы без порога при зеркалировании (оставляются как есть — проверьте их направление),
длительность бэктестов на 1-минутных свечах.

## Что изменилось в оптимизаторе (2.15.0)

**Пошаговый поиск вместо генетического** (`src/patternSearch.mjs`, по умолчанию; генетический
остался выбором в «Ручной настройке»):

1. каждый параметр сдвигается вверх и вниз по отдельности, плюс «макро»-сдвиги сетки (все отступы
   шире/уже, ближние/дальние ордера, объёмы ближе/дальше) — это и таблица «Влияние параметров»;
2. удачные сдвиги объединяются (сразу все или по одному), каждое принятое направление
   продолжается, пока есть прирост, затем повторяется весь шаг раунда;
3. шаг уменьшается вдвое, пересматриваются только параметры, которые на что-то влияют;
4. поиск детерминирован: после остановки он просто прогоняется заново, уже оценённые варианты
   берутся из архива без бэктестов.

**Оценка «лучше и по прибыли, и по просадке» с подбором депозита.** Прибыль и суммарная просадка
портфеля пропорциональны депозиту бота, поэтому вариант сравнивается с исходной при депозите
(в пределах ±30%), который уравновешивает оба показателя. Строгое сравнение при том же депозите
отбрасывало почти всё: любое изменение, добавляющее прибыль, добавляет и просадку. Рекомендуемый
депозит показывается в итогах и подставляется в «Создать бота».

**Улучшение должно быть широким.** Период поиска делится на ~полугодовые отрезки, монеты поиска —
на 2–3 группы; оценка поиска не выше медианы по этим срезам. Варианты, торгующие реже 60% сделок
исходной, отбрасываются.

**Поиск по всей истории по умолчанию.** Риск сетки определяют редкие обвалы; на последних 12–36
месяцах поиск находил «улучшения», которые проваливались на 2020–2022 (на имитации — просадка
в 13 раз больше). Период можно выбрать в окне запуска.

**Финалисты**: лучший вариант, самый простой из сохраняющих ≥ половины его прироста, затем
следующие по оценке. Проверка устойчивости (годы, невиденные монеты, плато, стресс-тест) идёт
с учётом рекомендуемого депозита; соседние настройки для плато выбираются детерминированно.

На имитации рынка (`test/sim/market.js`) старая схема (генетика, 12 мес., строгое сравнение)
воспроизводит ситуацию «исходная лучше всех», новая находит вариант +22% к прибыли при −18%
просадки с вердиктом «устойчиво». Имитация — не рынок: настоящий результат покажет прогон на Veles.
