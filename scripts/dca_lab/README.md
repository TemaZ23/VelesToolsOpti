# DCA Lab — симулятор и оптимизатор ботов Veles

Локальный бэктестер портфеля DCA-ботов veles.finance (режим «Сигнал») на минутных свечах
фьючерсов и оптимизатор параметров стратегии. Создан для доработки LONG_STRATEGY 22.X
([статья автора](https://telegra.ph/Obnovlenie-LONG-STRATEGY-121-09-05)).

Зачем, если есть бэктестер Veles: Veles считает один бот на одной монете за раз, а риск
стратегии — портфельный (десятки ботов на общей кросс-марже, одновременные проливы).
Здесь все боты симулируются синхронно по минутам: блокировка, динамическая блокировка
(«-1 при 5-м ордере»), кросс-маржа, ликвидация, лонг- и шорт-боты в режиме хеджирования.
Один прогон 63 монет × 3 года — ~3 секунды, поэтому можно перебирать тысячи вариантов.

Итоговые настройки обязательно перепроверяйте массовым бэктестом в Veles Tools —
это эталон; DCA Lab — быстрый фильтр идей.

**Результаты оптимизации LONG_STRATEGY:** [`output/dca_lab/REPORT.md`](../../output/dca_lab/REPORT.md),
готовые настройки бота — [`output/dca_lab/LONG_OPT_veles_settings.md`](../../output/dca_lab/LONG_OPT_veles_settings.md).

## Быстрый старт

```bash
pip install numpy numba pytest
# 1. минутные свечи Binance USDⓈ-M (≈145 МБ на монету за 2021-01..2026-09) + BTC для фильтра режима
PYTHONPATH=. python3 -m scripts.dca_lab.data --start 2021-01 --end 2026-09                # список WORK
PYTHONPATH=. python3 -m scripts.dca_lab.data --start 2020-06 --end 2026-09 --coins BTC    # фильтр BTC
PYTHONPATH=. python3 -m scripts.dca_lab.data --start 2021-01 --end 2026-09 --extend       # дописать историю назад
# 2. стратегия автора
PYTHONPATH=. python3 -m scripts.dca_lab.run baseline
# 3. эволюционный поиск на in-sample окне (long | short | crash)
PYTHONPATH=. python3 -m scripts.dca_lab.run optimize --problem long --gens 40 --min-deals 2000
# 4. отбор по in-sample, OOS-проверка, чувствительность → configs.json
PYTHONPATH=. python3 -m scripts.dca_lab.finalize --long output/dca_lab/evolve_long_<tag>.json
# 5. окна, профили размера, риск по дате старта → report_data.json → таблицы
PYTHONPATH=. python3 -m scripts.dca_lab.report --configs output/dca_lab/configs_report.json
PYTHONPATH=. python3 -m scripts.dca_lab.make_report > output/dca_lab/tables.md
# тесты механики движка
PYTHONPATH=. python3 -m pytest -q scripts/dca_lab/tests
```

Памяти нужно ~7 ГБ на 63 монеты × 5,6 года с сериями одной задачи (`series_for("long")`);
все серии меню сразу в 15 ГБ не помещаются. Запускайте тяжёлые задачи строго по одной — два процесса
одновременно ловят OOM.

## Модули

| Файл | Что делает |
|---|---|
| `data.py` | загрузка 1m свечей с data.binance.vision, кеш `cache/dca_lab/<SYMBOL>.npz` |
| `indicators.py` | индикаторы в трактовке Veles + меню серий `ИНДИКАТОР@ТФ` |
| `strategy.py` | `BotConfig` (вход, сетка, тейк, стоп, направление), `Sleeve` (набор ботов с размером и блокировкой), пресеты |
| `engine.py` | numba-движок: минутная синхронная симуляция всех ботов и стратегий |
| `portfolio.py` | `Market` (данные), `run` / `run_sleeves` / `run_batch`, метрики `Result` |
| `optimize.py` | задачи (LONG / SHORT / ловец проливов), пространство параметров, целевая функция, эволюция |
| `finalize.py` | отбор кандидатов по in-sample, OOS-проверка, чувствительность, сборка `configs.json` |
| `report.py` | метрики по окнам, профиль «размер бота → риск», риск по дате старта |
| `make_report.py` | Markdown-таблицы из `report_data.json` |
| `robust.py` | робастная доводка: Veles-округление, фолды + половины монет, плато, проверка вне отбора и на чужих монетах ([отчёт](../../output/dca_lab/ROBUST_REPORT.md)) |
| `regime.py` | режим рынка по BTC → множитель блокировки по дням |
| `veles_format.py` | настройки бота в терминах интерфейса Veles |
| `run.py` | CLI (`baseline`, `optimize`) |

## Как трактуются настройки Veles

* Все условия — «На закрытии бара»: для минуты *i* берётся последний закрытый бар своего ТФ
  (`j = (i+1)//k - 1`). Состояние условия держится до следующего закрытия бара.
* Первый ордер — лимитный с отступом от цены сигнала; подтяжка отменяет сделку, если цена
  ушла на N% в прибыль до исполнения.
* Ордера 2..N — по рынку на закрытии минуты, когда (а) цена ниже минимального отступа
  от цены входа и (б) выполнены все сигналы ордера. Ордер без сигналов — лимитный.
* Тейк «по сигналу» — рыночный, когда P&L ≥ минимального и выполнены все условия тейка.
* Стоп «по сигналу, от средней» — рыночный, когда цена ниже средней на `sl_indent`% и есть сигнал.
* Сигнальные индикаторы: RSI/CCI/Стохастик «уровни» — пересечение 30/−100/20 снизу вверх
  (для шорта — 70/+100/80 сверху вниз); Боллинджер/Кельтнер — закрытие за полосой;
  Turtle Zone — закрытие за внутренней зоной (лог-шкала, сглаживание Элерса, InnerAmp 5.6);
  MACD — пересечение нуля.
* Номинальный объём — оборот бара в USDT (Binance; на Bybit обороты ниже, фильтр 100k/час
  на ликвидных монетах всё равно почти всегда выполнен).
* Комиссии: maker 0.02%, taker 0.055% (Bybit), фандинг 0.01% / 8 ч (лонг платит).
* Ликвидация: эквити по худшим ценам минуты ≤ 1% номинала всех позиций (кросс-маржа).

## Метрики

* `avg_month_pct` — средняя доходность в месяц, % начального депозита (как считает автор).
* `cmgr_pct` — среднемесячный сложный рост.
* `dd_abs_pct` — максимальная просадка (пик эквити → эквити по худшим ценам минут)
  в % начального депозита. Именно она линейно растёт с размером бота.
* `eff` — эффективность: `avg_month_pct / dd_abs_pct`. Не зависит от размера бота —
  главный критерий качества стратегии. Доходность при допустимой просадке X% ≈ `eff × X`.
* `concurrent_mae_pct()` — «Суммарный МПУ» как в Veles Tools (сумма MAE одновременно открытых сделок).

## Ограничения

* Данные Binance вместо Bybit: цены почти совпадают, но экстремальные «фитили»
  (например, 10.10.2025) на разных биржах разные.
* Внутри минуты порядок high/low неизвестен; рыночные ордера исполняются по close минуты.
* Turtle Zone — аппроксимация (исходник индикатора закрыт), поэтому тейки могут
  немного отличаться от Veles.
* Делистинги учитываются как принудительное закрытие на последней свече монеты;
  монеты, которых нет на Binance (CRO, MNT), не моделируются.
