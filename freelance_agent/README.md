# Freelance Agent

Агент на Claude, который ведёт фриланс-заказ целиком: находит заказы, оценивает их, пишет отклики,
переписывается с клиентом, выполняет работу (Claude Agent SDK, то есть Claude Code как библиотека),
сам проверяет результат, сдаёт его и учитывает оплату. Вы управляете им из Telegram в одно нажатие.

Главное правило в коде — **агент не тратит деньги, которые не окупаются**:

- откликается только когда ожидаемая прибыль положительна:
  `P(победы) × (цена − комиссия − бюджет ИИ на выполнение) − стоимость отклика`;
- считает каждый цент API (по `usage` из каждого ответа) и проверяет лимиты **до** вызова;
- стоп-лосс: если расходы на LLM превысили заработанное больше чем на `stop_loss_usd`, новые
  отклики останавливаются до первой оплаты (уже выигранные заказы доделываются);
- у выполнения каждого заказа жёсткий потолок в долларах (`max_budget_usd` в Agent SDK) —
  не больше 25% чистой цены заказа и не больше $8 по умолчанию;
- отчёт `/stats` показывает прибыль **после** подписки и прочих фикс. расходов.

## Честно о заработке

Гарантировать доход не может ни один код: деньги приносят заказы, которые выбрал клиент. Агент
гарантирует другое — что потери ограничены вашими лимитами, а каждый отклик экономически
оправдан. Порядок цифр (команда `freelance-agent estimate`):

| | стоимость |
|---|---|
| оценка одного заказа (Claude Haiku 5.5) | ≈ $0.0005 |
| один отклик (Claude Opus 5.5) | ≈ $0.04–0.08 |
| выполнение заказа (Claude Opus 5.5, Agent SDK) | $0.5–10, всегда ≤ лимита заказа |
| поиск заказов в месяц при настройках по умолчанию | ≈ $10–25 (лимит $2/день) |

Заказ на $100 на Freelancer.com: комиссия $10, ИИ $1.5, ~20 откликов на одну победу ($1.2) →
маржа ≈ $87. Подписка $20 окупается одним таким заказом в несколько месяцев; реальная
конверсия новых аккаунтов без отзывов бывает 1–5%, агент учится на своей статистике.

Агент работает через **Claude API** (оплата по факту). Подписка Claude Pro/Max — отдельный
продукт; если вы её оплачиваете, впишите её в `budget.fixed_monthly_costs_usd`, и отчёт будет
считать окупаемость с её учётом.

## Как устроен цикл

```
FL.ru RSS ─┐                      бесплатно            Haiku 5.5            экономика
Freelancer ├─► новые заказы ─► стоп-слова, бюджет, ─► оценка: можно ли ─► EV > 0 ? ─► Opus 5.5:
RSS        ┘                   возраст, конкуренция    сделать ИИ, этично,             отклик
                                                       сложность, цена                    │
                    ┌─────────────── Telegram: ✅ / ✏️ / ❌ (или авто в режиме semi/auto) ◄─┘
                    ▼
              ставка/отклик ─► переписка (черновики ответов, требования, критерии приёмки)
                    │
              вас выбрали ─► Agent SDK в песочнице, лимит $ ─► ревью по критериям ─► доработка
                    │                                                                  │
              оплата учтена ◄── milestone / кнопка «Оплачено» ◄── сдача (zip + сообщение) ◄┘
```

## Площадки

| площадка | поиск | отклик | переписка | сдача | оплата |
|---|---|---|---|---|---|
| **Freelancer.com** (официальный API) | авто | авто или по кнопке | авто или по кнопке | вложение в чат | авто по milestone |
| **FL.ru** (RSS) | авто | вы вставляете готовый текст | вы пересылаете сообщения клиента реплаем | вы отправляете zip | кнопка «Оплачено» |
| любой RSS (WeWorkRemotely и т.п.) | авто | вручную | реплаем | вручную | `/paid` |

Upwork, Kwork, Fiverr, Habr Freelance сознательно не подключены: у них нет публичного API для
откликов, а боты и скрейпинг запрещены правилами — за это блокируют аккаунт. FL.ru тоже не
автоматизируется дальше чтения RSS по той же причине. Без PRO на FL.ru агент берёт только
заказы «для всех» (`sources.flru.pro_account`).

Агент пишет от вашего имени и только правду из `profile`: не выдумывает опыт и портфолио, не
уводит оплату с площадки, на вопрос «это ИИ?» отвечает честно. Неэтичные заказы (накрутка
отзывов, курсовые, спам) отсекаются и стоп-словами, и оценкой модели.

## Установка

Нужен Python 3.11+.

```bash
cd freelance_agent
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e .
freelance-agent init        # создаст config.yaml и .env
```

1. **Ключ Claude API** — <https://platform.claude.com/settings/keys>, в `.env` как
   `ANTHROPIC_API_KEY`. Лучше создать отдельный workspace с лимитом расходов: это потолок на
   стороне Anthropic, который сработает даже при ошибке в настройках.
2. **Telegram-бот** — создайте у @BotFather, токен в `.env` (`TELEGRAM_BOT_TOKEN`). Запустите
   `freelance-agent run`, отправьте боту `/start` — он ответит ваш `chat_id`; впишите его в
   `config.yaml` (`telegram.chat_id`) и перезапустите. Сообщения из других чатов игнорируются.
3. **Freelancer.com (по желанию)** — OAuth-токен с <https://developers.freelancer.com> в `.env`
   (`FREELANCER_OAUTH_TOKEN`). Без токена поиск работает, ставки отправляете вы.
4. **Профиль** — заполните `profile` в `config.yaml`. Отклики цитируют только его.
5. Проверка: `freelance-agent check` (бесплатно: ключ, модели, площадки, бот, песочница).

### Где запускать: песочница исполнителя

Исполнитель запускает код, который Claude пишет по тексту чужого заказа. Песочница ОС ограничивает
его рабочей папкой и списком доменов (pypi/npm). Без неё агент **отказывается** выполнять заказы
(`executor.allow_unsandboxed: true` — только на одноразовой машине). `freelance-agent check`
по-настоящему запускает песочницу и говорит, работает ли она у вас.

- **Linux VPS или WSL2 на Windows (рекомендуется)**: `sudo apt-get install -y bubblewrap socat`,
  дальше установка как выше. Проверено: на Linux с bubblewrap проверка песочницы проходит.
- **Docker**: в образе всё установлено, но bubblewrap внутри контейнера нужны права на создание
  namespaces, поэтому в `docker-compose.yml` стоят `seccomp=unconfined` и `apparmor=unconfined`.
  Работает ли это на вашем хосте, покажет `check`.

```bash
docker compose run --rm agent init      # config.yaml и .env появятся в ./agent-data
docker compose run --rm agent check
docker compose up -d
```

## Команды

```
freelance-agent scan        бесплатный обзор рынка: что прошло фильтр, без LLM
freelance-agent smoke-llm   один реальный вызов оценки (< $0.01), проверка ключа и учёта
freelance-agent once        один полный цикл
freelance-agent run         работать постоянно (поиск каждые poll_interval_minutes)
freelance-agent stats       выручка, расходы, прибыль, конверсия
freelance-agent paid ID СУММА [ВАЛЮТА]   учесть оплату вручную
freelance-agent estimate --price 100 --complexity small   окупаемость заказа
```

В Telegram: `/stats`, `/jobs`, `/scan`, `/pause`, `/resume`, `/client ID текст`, `/won ID`,
`/work ID`, `/paid ID сумма [валюта]`. **Ответ реплаем на карточку** заменяет текст отклика или
ответа клиенту, пересылает агенту сообщение клиента или отправляет результат на доработку.

## Режимы автономности (`autonomy.mode`)

- `manual` (по умолчанию) — всё исходящее ждёт вашего нажатия. Начните с него.
- `semi` — на Freelancer.com ставки с оценкой ≥ `auto_bid_min_score` и ценой ≤ `auto_bid_max_usd`
  уходят сами; ответы клиентам и сдача ждут вас.
- `auto` — на Freelancer.com агент сам ставит, отвечает, принимает заказ и сдаёт результат,
  прошедший ревью. Вопросы про цену, сроки, споры и возвраты всё равно приходят вам.

## Безопасность

- Текст заказов и сообщений клиентов считается недоверенным: в промптах он изолирован тегами,
  модель проинструктирована не выполнять из него команды.
- Исполнитель: только инструменты Read/Write/Edit/Glob/Grep/Bash, без веба по умолчанию,
  `setting_sources=[]` (не читает ваши настройки Claude Code), токены Telegram и Freelancer
  вычищены из его окружения, песочница ОС обязательна (`executor.allow_unsandboxed` — только
  на одноразовой машине).
- Двойное нажатие кнопки не отправит отклик дважды; при ошибке кнопку можно нажать снова.

## Что проверено

`pytest` — 44 теста, включая сквозные сценарии «заказ с FL.ru от RSS до оплаты» и
«полностью автоматический заказ на Freelancer.com» (реальный код пайплайна и Anthropic SDK,
подменён только сетевой транспорт), и живой запрос к FL.ru и Freelancer.com
(`pytest -m live`). Парсеры проверены на реальных ответах площадок (`tests/fixtures`).

Docker-образ собран и запущен: `init`, `scan` и `check` работают внутри контейнера, проверка
песочницы корректно отказывает там, где bubblewrap не может создать namespaces.

Не проверено (нужны ваши ключи и аккаунты): реальные вызовы Claude API (`smoke-llm` проверит
за доли цента), отправка ставок и сообщений на Freelancer.com (эндпоинты взяты из официального
SDK Freelancer), живой бот Telegram, полный прогон исполнителя в песочнице. Начните с `check`,
`scan`, `smoke-llm` и режима `manual`.

```bash
pip install -e ".[dev]" && pytest            # все тесты
pytest -m "not live"                          # без сети
```
